# Hammerspoon integration

K811의 노브를 매크로 휠로, 조이스틱과 미디어 버튼을 마우스 동작으로 바꾼다. 미디어 키와 노브는 Karabiner가 `f16`~`f20`으로 번역해 넘겨주고([`../karabiner/`](../karabiner/) 먼저 설정할 것), 조이스틱은 장치가 화살표 키를 그대로 내므로 번역 없이 받는다.

## 매핑

| 입력 | Karabiner 번역 | 동작 |
| --- | --- | --- |
| 노브 반시계 / 시계 | `f16` / `f17` | 매크로 휠. 한 칸에 한 항목 |
| 이전 곡 | `f18` | 좌클릭 |
| 다음 곡 | `f19` | 우클릭 |
| 재생/일시정지 (짧게) | `f20` | 휠(가운데) 클릭 |
| 재생/일시정지 + 조이스틱 | `f20` + 화살표 (번역 없음) | 커서 미세 이동. 네 방향과 대각선 |

매크로 휠이 열려 있는 동안에만 두 버튼의 뜻이 바뀐다.

| 입력 | 휠이 열려 있을 때 |
| --- | --- |
| 재생/일시정지 | 고른 항목을 붙여넣고 닫는다 |
| 이전 곡 | 아무것도 넣지 않고 닫는다 |
| 엔터 (키보드) | 확정 |
| esc (키보드) | 취소 |

엔터와 esc는 휠이 열려 있는 동안에만 가로챈다. 닫혀 있으면 손대지 않으므로 평소에는 엔터는 엔터고 esc는 esc다. 이 eventtap은 출처 장치를 알 수 없어서 본 키보드의 엔터·esc도 같이 먹는데, 휠은 화면을 덮고 뜨는 모달이라 그게 맞는 동작이다.

> 이 환경은 `init.lua`에서 escape를 `f13`으로 remap 해 두었다. 실제 esc 키가 `f13`으로 들어오므로 `knob_mapping.lua`의 `KEYS`는 둘 다 잡는다. remap을 걷어냈다면 `wheelEscapeRemap` 줄을 지우면 된다.

## 매크로 휠

노브를 돌리면 화면 가운데에 둥근 피커가 뜬다. 등록된 개수만큼 조각이 나뉘고 조각마다 축약 이름이, 가운데에는 고른 항목의 전체 이름과 `2 / 5` 같은 위치가 나온다. 손을 멈춘 채 `IDLE_TIMEOUT`이 지나면 아무것도 넣지 않고 닫힌다.

### 매크로 추가·수정·삭제

항목은 `macro_wheel.lua` 맨 위 `M.macros`에 기본값으로 들어 있다. **내 목록은 `~/.hammerspoon/init.lua`에서 통째로 갈아 끼운다.** 모듈 파일을 고치면 다음에 새 버전을 `cp` 할 때 목록이 같이 덮이고, 이 레포는 공개라 사내 문구나 사람 이름이 든 상용구를 여기에 두면 그대로 공개된다.

```lua
knobMapping = require('knob_mapping')
knobMapping.start()

knobMapping.wheel.macros = {
  { short = "새 대화", label = "/new", text = "/new" },
  { short = "정리",    label = "/clear", text = "/clear" },
}
```

고치고 나면 `⌘⌥R`로 다시 불러들인다. 표를 바꾸면 조각 수도 따라간다.

| 필드 | 쓰임 |
| --- | --- |
| `short` | 조각에 찍히는 축약 이름 |
| `label` | 가운데에 찍히는 이름. 없으면 `short` |
| `text` | 확정했을 때 붙여넣을 텍스트 |

지금 뭐가 등록돼 있는지는 이렇게 본다.

```sh
hs -c "hs.inspect(knobMapping.wheel.macros)"
```

### 한 칸이면 언제나 1번

인코더는 절대 위치를 주지 않는다. 지금 몇 번째 칸인지 장치는 모르고 방향만 보낸다. 그래서 휠이 닫힐 때 선택을 버리고 다음에 열릴 때 항상 1번부터 센다. 홈은 화면에 그리지 않는 '선택 없음' 상태다.

- 시계 방향 한 칸 → 1번, 두 칸 → 2번
- 반시계 방향 한 칸 → 마지막 항목. 뒤쪽 항목도 한 칸 거리에 둔다
- 한 바퀴를 돌면 제자리다. 다섯 개를 등록했으면 여섯 칸째가 다시 1번이다

그래서 순서를 바꾸면 손에 익은 칸 수가 어긋난다. 항목을 더할 때는 뒤에 붙이는 편이 낫다.

### 붙여넣은 자리에 커서 세우기

버전 번호처럼 매번 채워 넣는 자리가 있으면 `knobMapping.wheel.caret`을 텍스트 중간에 한 번 끼워 넣는다. 붙여넣기가 끝난 뒤 그 자리까지 왼쪽 화살표로 되돌아간다.

```lua
text = "해당 이슈 " .. knobMapping.wheel.caret .. " 버전에 수정 반영될 예정이오니 …"
```

화면에 찍히지 않는 제어문자(`\1`)라 본문과 겹치지 않는다. 화살표는 글자 단위로 움직이므로 되돌아갈 거리는 바이트가 아니라 코드포인트로 센다. 붙여넣기를 비동기로 처리하는 앱에서는 화살표가 글자보다 먼저 도착할 수 있어서 `CARET_DELAY`만큼 기다렸다 보낸다. 그래도 어긋나면 이 값을 올린다.

### 타이핑이 아니라 붙여넣기

한 글자씩 타이핑하면 한글 입력기가 켜져 있을 때 자모가 섞인다. 클립보드에 넣고 `Cmd+V`를 보내면 입력기를 타지 않고 긴 텍스트도 한 번에 들어간다. 원래 클립보드는 `RESTORE_DELAY` 뒤에 되돌리되, 그 사이 사용자가 다른 것을 복사했으면 손대지 않는다.

## 조이스틱 미세 이동

재생/일시정지를 누르고 있는 동안에만 조이스틱이 커서를 움직인다. 톡 치면 `joy.nudge` 픽셀만 가고, 계속 밀고 있으면 `joy.ramp` 동안 `joy.minSpeed`에서 `joy.maxSpeed`까지 `joy.curve` 곡선으로 붙는다. 두 방향이 같이 눌리면 대각선으로 가며 축별 속도를 `DIAGONAL`로 줄인다.

버튼을 누르지 않았을 때 화살표는 그냥 화살표다. 이 eventtap은 이벤트의 출처 장치를 알 수 없으므로 조건 없이 삼키면 모든 키보드의 화살표가 같이 죽는다. 대신 key down을 먹었으면 짝이 되는 key up도 먹는다 — 버튼을 먼저 뗐다고 key up만 앱에 흘리면 그 앱은 화살표가 계속 눌려 있다고 본다.

이동을 auto-repeat에 얹지 않고 60Hz 타이머로 만드는 이유는 하나다. repeat 간격은 시스템 키보드 설정을 따라가므로 커서 속도가 그것에 묶이면 안 된다.

### 조이스틱은 왜 강제 release를 겪지 않나

노브와 달리 조이스틱은 재생/일시정지를 밀어내지 않는다. 화살표가 consumer 리포트가 아닌 키보드 리포트로 오기 때문이다. 버튼을 누른 채 네 방향을 다 움직여도 `f20` key up은 손을 뗄 때 한 번만 온다.

```
258.274  f20 down          ← 버튼 누름
258.558  f20 down (repeat)
258.564  up  down          ← 조이스틱, f20 은 그대로 눌려 있음
260.212  down up
260.368  f20 up            ← 손을 뗄 때 처음 올라온다
```

그래서 버튼이 눌려 있다는 사실을 그대로 믿고 쓴다. 조이스틱을 쓴 누름은 휠 클릭으로 해석하지 않는다.

## 설치

```sh
cp knob_mapping.lua macro_wheel.lua knob_capture.lua ~/.hammerspoon/
```

`~/.hammerspoon/init.lua`에 추가한다. `macro_wheel`은 `knob_mapping`이 알아서 불러온다.

```lua
knobMapping = require('knob_mapping')
knobMapping.start()

-- 진단이 필요할 때만 knobCapture.start() 를 호출한다
knobCapture = require('knob_capture')
```

## 노브가 더는 커서를 움직이지 않는 이유

예전에는 노브가 커서를 가로로 옮기고 재생 버튼과 조합하면 세로로 옮겼다. 조이스틱 미세 이동이 생기면서 둘 다 조이스틱이 더 잘하게 됐고, 세로 조합은 애초에 정확해질 수 없는 판정이었다.

K811은 consumer HID 리포트에 usage를 **한 번에 하나만** 담는다. 그래서 재생/일시정지를 누른 채 노브를 돌리면 하드웨어가 재생 버튼을 강제로 release 한다. 실측하면 회전 **5~13ms 전**에 key up이 들어온다.

```
605.432  f20 down          ← 재생 버튼 누름
  ...    f20 down (auto-repeat 1.09초)
606.526  f20 up            ← 강제 release
606.539  f16 down          ← 노브 회전, 13ms 뒤
```

눌림 상태를 되찾을 방법도 없다. 강제 release 뒤에는 버튼을 계속 누르고 있어도 장치가 `f20`을 다시 보내지 않는다. 회전이 12초 동안 이어지는 사이 `f20 down`은 한 번도 오지 않았다. 그래서 버튼을 뗀 직후 짧은 창 안에 노브가 들어오면 조합으로 치는 수밖에 없었고, 그 창은 좁힐 수만 있고 정확해질 수는 없었다.

노브를 매크로 휠에 넘기면서 그 창 판정(`COMBO_WINDOW`·`VERTICAL_IDLE`)과 창을 열어 두려고 휠 클릭을 미루던 `CLICK_DELAY`까지 통째로 사라졌다. 지금 노브는 재생 버튼과 아무 관계가 없으므로 강제 release가 일어나도 잃을 것이 없다.

## 튜닝

`knob_mapping.lua` 상단 상수.

| 상수 | 기본값 | 의미 |
| --- | --- | --- |
| `LONG_PRESS` | `0.7` | 이보다 오래 눌렀다 떼면 휠 클릭을 내지 않는다. 조이스틱을 쓰려다 만 누름이다 |
| `DIAGONAL` | `0.7071` | 대각선일 때 축별 속도 보정 |

`macro_wheel.lua` 상단 상수.

| 상수 | 기본값 | 의미 |
| --- | --- | --- |
| `IDLE_TIMEOUT` | `4` | 회전이 끊긴 뒤 저절로 닫히기까지의 시간 |
| `RESTORE_DELAY` | `0.4` | 붙여넣기 뒤 원래 클립보드를 되돌리기까지 기다리는 시간 |
| `CARET_DELAY` | `0.15` | 붙여넣기 뒤 커서를 되돌리기까지 기다리는 시간 |
| `look.outerRadius` | `148` | 휠 바깥 반지름 |
| `look.innerRadius` | `62` | 가운데 구멍 반지름 |
| `look.labelRadius` | `105` | 축약 이름을 놓는 반지름 |
| `look.sliceGap` | `1.2` | 조각 사이를 벌리는 각도 |

조이스틱 감각은 `joy` 표에 모여 있고 돌아가는 중에도 바꿀 수 있다. 손끝에 맞출 때는 파일을 고치고 다시 불러들이는 것보다 이쪽이 빠르다.

```sh
hs -c "knobMapping.tune{ maxSpeed = 5, ramp = 0.8 }"   # 더 느리게
hs -c "hs.inspect(knobMapping.tune{})"                  # 현재 값 보기
```

| `joy` | 기본값 | 의미 |
| --- | --- | --- |
| `tick` | `1/60` | 커서를 다시 그리는 간격. 바꾸면 다음 밀기부터 적용 |
| `nudge` | `2` | 조이스틱을 톡 쳤을 때 움직일 픽셀 |
| `holdDelay` | `0.12` | 이 시간을 넘겨 밀고 있으면 활주로 넘어간다 |
| `minSpeed` | `1` | 활주 시작 속도 (tick 당 픽셀 = 60px/s) |
| `maxSpeed` | `8` | 활주 최고 속도 (tick 당 픽셀 = 480px/s) |
| `ramp` | `0.5` | 최고 속도까지 걸리는 시간 |
| `curve` | `1.5` | 붙는 곡선. `1`이면 직선이고 크면 초반이 느려진다 |

기본값의 실측 결과는 이렇다. 버튼을 누른 채 한 방향으로 밀었을 때의 누적 이동 거리다.

| 미는 시간 | 이동 |
| --- | --- |
| 톡 치기 | 2px |
| 0.3초 | 20px |
| 0.6초 | 110px |
| 1.0초 | 302px |

0.62초에 최고 속도(480px/s)에 닿는다. `holdDelay` 0.12초 뒤부터 `ramp` 0.5초 동안 붙기 때문이다.

## knob_capture.lua

장치가 실제로 어떤 이벤트를 보내는지 `~/.hammerspoon/knob_capture.log`에 기록하는 진단 모듈. 이벤트를 소비하지 않으므로 캡처 중에도 원래 동작은 유지된다.

```lua
knobCapture.start()
knobCapture.stop()
```

> **모든 키 입력이 기록된다.** 진단이 끝나면 `stop()` 하고 로그 파일을 지울 것.
